## Design decisions (beyond the prompt)
- Plies: `games.ply` = moves made; even ply → White to move.
- Clocks start after both players have made their first move (Lichess-style): plies 1 and 2 cost no time and get no increment; each first move has a 30 s `first_move_deadline`; missing it aborts the game (no rating).
- Insufficient mating material for timeouts: the Edge Function computes it per side (port of dartchess `hasInsufficientMaterial`) and passes it to `apply_move`, which stores it on the game (`white_can_mate`, `black_can_mate`). `apply_move`, `claim_timeout` and the sweep all use the stored flags, so no chess code is needed in SQL.
- Matchmaking: one transaction-level advisory lock serialises `join_queue` (plus `FOR UPDATE SKIP LOCKED` on the queue). Simple and provably no double pairing at our traffic. A queued user learns about the pairing by calling `join_queue` again (returns the active game) or via Realtime on `games`.
- Invite games keep `created_by`; colours are assigned on join.
- Errors are raised as `P0001` with the code as message (`STALE`, `NOT_YOUR_TURN`, `GAME_OVER`, ...); the Edge Function maps them to JSON `{error: code}`.
