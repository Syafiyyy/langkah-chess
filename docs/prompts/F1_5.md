## 1. Analysis engine flow
- Reuse `EngineService` (one engine; review never runs while a game vs the bot is running). Add an analysis API that streams results per ply: `analyse(fens, {depth or movetime}) → Stream<PlyEval>`; cancellable (leaving the screen stops the search).
- Per position: score (cp or mate) and best move + PV. Convert every score to White's point of view in one place (UCI scores are side-to-move POV).
- Settings: pick a default that analyses a 40-move game in roughly 30–45 s on a phone (start with movetime ~250 ms or depth ~14; measure and tune). Show progress (ply x / n) and fill the graph progressively.
- Cache results in sqflite keyed by game id + analysis settings + engine version, so reopening is instant. Re-analysis only on request.

## 2. Review math (pure Dart, unit-tested)
- Win% from centipawns (Lichess): `50 + 50 * (2 / (1 + exp(-0.00368208 * cp)) - 1)`; mate → 100 / 0 for the winning / losing side.
- Move labels from the mover's win% drop (chess-domain skill): >= 15 blunder (??), >= 10 mistake (?), >= 5 inaccuracy (?!). "Best" when the played move equals the engine's best move. No label when the position was already completely won/lost in a way the drop doesn't matter (document the rule you choose).
- Per-move accuracy (Lichess formula, verify against their source if Context7/web allows): `103.1668 * exp(-0.04354 * winDrop) - 3.1669`, clamped 0–100. Game accuracy per side = mean of that side's move accuracies (document if you use Lichess's weighted version instead).
- Tests: conversion, POV flip, labels at boundaries, mate handling, accuracy for a known short game.
