## 1. Architecture (ADR-0006)
- `features/play_ai/domain/`: pure Dart, no Flutter imports.
  - `GameState` (immutable): dartchess position, list of moves (UCI + SAN), position history for repetition, clocks, status, result + termination, player colour, bot level, time control.
  - `GameController`: applies moves, takeback, resign, timeout, computes outcome. Injected `Clock` (see 3) so tests control time.
- `features/play_ai/application/`: Riverpod notifier wrapping the controller + talking to `EngineService`.
- `features/play_ai/presentation/`: screens/widgets only render state and dispatch actions.
- Delete the F0 smoke screen once the real game screen replaces it (keep its tests' intent).

## 2. Engine strength levels
- 8 levels like Lichess. Check the engine's real option ranges by sending `uci` and reading the `option` lines (Stockfish's `UCI_Elo` has a minimum around 1320, so the lowest levels can't use UCI_Elo alone).
- Low levels: `Skill Level` + small `depth`/`movetime`. Higher levels: `UCI_LimitStrength true` + `UCI_Elo`. Put the mapping in one table in domain code, label each level with an approximate rating, and unit-test the mapping.
- Bot thinking time must also respect the bot's own clock when the game is timed (never think longer than a safe fraction of remaining time).
- Warm the engine (`newGame()`) when the game screen opens so the first reply is fast.
- Add `setOptions` support to EngineService (with `isready` wait) without breaking the existing rules (stdout listened once, serialised commands).

## 3. Clock
- Time controls: unlimited, 3+2, 5+0, 10+0, 15+10, 30+0, custom (minutes + increment).
- Use a monotonic stopwatch (elapsed since turn start), NOT a periodic timer that subtracts seconds (v1 bug: drift). The UI ticker only repaints.
- Increment added after a completed move. Clock starts after White's first move (like Lichess) — document the choice.
- Pause both clocks when the app goes to background; resume on return (offline game only).
- Timeout rule from the chess-domain skill: the side whose flag falls loses, unless the OTHER side has insufficient mating material → draw. Own tests.

## 4. Game rules and flow
- Results: checkmate, stalemate, insufficient material, threefold repetition (track positions by placement + side + castling + ep, not counters), 50-move rule (auto-draw at 75 moves; claimable at 50 is optional), resignation, timeout.
- Promotion: chessground's promotion selector. Castling, en passant through dartchess only.
- Takeback vs AI: undo the last full move pair (yours + bot's); disabled while the bot is thinking; cancels the bot's search.
- Flip board. Choose colour: white / black / random. When the player is black, the bot moves first using the chosen level (v1 bug: first move ignored difficulty).
- Move list in SAN; tapping a move shows that position read-only (board returns to live on "back to game"); never mutates the game.
- Last-move and check highlights (chessground).
- Game-over sheet: result, termination reason, move count, duration; actions "New game", "Rematch (swap colours)", "Home". History is saved exactly ONCE per game (v1 bug: twice), from the controller when the game ends, not from UI buttons.
- Autosave the in-progress game; if the app is killed mid-game, offer "Resume game" on next launch.

## 5. Local history
- Store finished games on device (sqflite or drift; pick one, explain why in STATE). Fields: id, date, player colour, bot level, time control, result, termination, PGN (with headers), final FEN, move count, duration.
- History screen: list (newest first) with filter All / Wins / Losses / Draws; tap → replay screen (step through moves, flip board).
- Share PGN (share_plus) and copy PGN to clipboard.
- PGN round-trip test: export → parse with dartchess → same moves and result.
